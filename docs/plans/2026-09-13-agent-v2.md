# Party agent v2 implementation

Approved design: replace the linear party pipeline with a bounded, resumable,
evidence-driven tool agent. This is the implementation record of the design
approved in conversation, not a proposal to expand product scope.

## Global Constraints

- The agent automatically maintains a provisional shared draft. Only the Host
  may approve an exact ready draft revision before real Silpo cart writes.
- Manual Add, quantity changes, Delete, and synchronization have the same
  draft/approval boundary. Checkout stays manual. The Host prepares the Silpo
  cart, store and slot in Silpo.
- Start incrementally without waiting for every participant. Preserve stable
  requests/artifacts and invalidate only affected dependents.
- Participant private context is visible only to that participant and the agent,
  not other members or the Host. Explicit shared chat remains shared.
- Fetch personal restrictions/favorites under that participant's credentials;
  commerce uses the Host's credentials. Empty successful context means no
  restrictions. Failures retain known restrictions, report a limitation, and
  must not manufacture an extra confirmation requirement.
- Deterministic code owns authorization, hard restriction enforcement, units,
  servings, package rounding, totals, revisions, readiness and write verification.
  Unknown product/composition evidence must never be labeled safe.
- Recipe source/details first; generated recipes are allowed with explicit
  origin, servings, complete quantities/units and preparation steps. Do not
  silently drop required ingredients or invent source URLs.
- Only authenticated tools/list proves live MCP schemas. Existing fixtures and
  documentation are not a live verification. Unsupported contracts fail closed.
- Supabase is central state plus Realtime and Queues. Keep useful existing OAuth,
  extraction, arithmetic, authentication, memberships, tests and read-back pieces.
- Never apply remote migrations, mutate a real customer's cart, publish, push,
  expose secrets or reset existing data during local implementation.
- Bound a logical run to 20 model steps, 3 search revisions per requirement,
  3 concurrent independent reads, serial draft mutations, 60-second worker
  slices, 3 transient attempts, and stop after 2 no-progress steps.
- Persist SDK messages/tool results and checkpoints between one-step
  ToolLoopAgent invocations (`isStepCount(1)` in installed AI SDK 7).
- Do not claim deployment, live MCP/model validation or an evaluation threshold
  without actually running the corresponding checks.

## Task 1: Versioned private state, deterministic draft domain and durable storage

Create focused modules under `src/lib/ai/agent-v2/` for validated workspace,
requests, context, artifact/evidence references, revisions, task outcomes,
deterministic invalidation and draft calculation. Reuse planning arithmetic
where correct. Expose clear exported types and functions for later tasks.

Requests need stable IDs and typed add/remove/replace/quantity/servings/eater
edits. Own requests default to own eater; group eaters are explicit; unsubmitted
members are not indifferent. Pure questions don't mutate the draft.
Retain constraints per participant/version/source, union declared hard rules,
distinguish empty versus error and retain known constraints on refresh errors.
Recipe/product validation must consult actual ingredient/composition evidence,
return unknown for unsupported semantic restrictions, and block readiness on
unknowns rather than trusting an LLM safe flag. Do not use a tiny denylist as a
complete dietary safety oracle. Public projections omit private reasons/evidence.
Separate input and draft revisions; meaningful changes invalidate dependencies.

Add an additive Supabase migration plus a server-only repository layer:
private per-party workspace and checkpoints/steps, source events, queue,
versioned sanitized draft/activity projections, cart-operation ledger.
Use explicit grants and RLS, service-only raw workspace/checkpoint data, and
recipient-scoped assistant questions in existing chat. Remove shared profile
policy and historical private profile JSON fingerprints without deleting
proposal history. Preserve existing tables and historical basket/proposals.
Atomic event/revision/run/queue enqueue; per-party lease with monotonic fence;
CAS checkpoint/draft writes; claim with SKIP LOCKED and expired lease recovery;
only acknowledge persisted steps; stale workers cannot publish.
Extend statuses for waiting_for_input, blocked, cancelled and superseded where
needed. Public realtime publishes only safe tables. Provide local SQL security
and concurrency checks. No remote migration execution.

Write failing focused tests before implementing state/invalidation/privacy/
revision/readiness behavior, then pass focused and full tests. Read applicable
Supabase skills and docs before schema work. Record exact exports/RPC contracts
and integration instructions in the report for Tasks 2-4.

## Task 2: Evidence-backed recipe/catalog capabilities and safe cart reconciliation

Build focused modules under `src/lib/ai/agent-v2/` using Task 1's domain types.
Implement application tools/services for recipe source resolution or generated
recipe validation, requirement derivation, product search/details/substitutions,
known-ID selection and deterministic draft review. Keep model instructions and
domain services separate. Reuse useful source parser and package arithmetic;
remove v2 reliance on undocumented sf-ecom recipe endpoints. Harden untrusted
recipe fetching against private/reserved targets, redirects and unbounded bodies.

Implement explicit MCP adapters/capability validation from supported tool schema
contracts; unsupported schemas return a blocker (no heuristic nested key guessing).
Keep OAuth and MCP transport. Add a read-only authenticated contract capture
command that writes sanitized schema fixtures (never credentials/personal data).
Do not pretend captured live schemas are available in this environment.
Honor active cart -> details -> available slots; validate selected slot.
Search batches <=30. Evidence records IDs/store, composition/attributes,
packaging, price, stock and retrieval time. Required variant correctness beats
price; missing safety evidence is unverified. Limit retries with structured
outcomes and Retry-After handling, no retries of ambiguous writes.

Implement a testable cart reconciliation service that requires Host authority
and immutable approved ready revision. Re-read cart/store/slot/product prices,
availability before writes. Relevant changes (including higher price) require
new approval. Persist operation before first write with expected snapshot,
approved revision and exact intended changes. Use absolute quantities for
app-managed quantities, preserve external lines; overlapping external edits
conflict. Read back additions/removals/exact counts/totals/validation failures.
After uncertain write outcome reconcile before retry. Pending new drafts cannot
change an approved operation. Expose repository-based integration for Task 4.

Use failing tests first for wrong variant, missing evidence, batch bounds,
contract mismatch, unavailable slot, generated recipe completeness, unsafe
sources, cart external changes, timeout reconciliation, stale approval and
duplicate application. Full tests once before reporting.

## Task 3: Actual resumable tool loop, context, worker and shared harness

Wire Task 1 storage and Task 2 services into a real AI SDK 7 ToolLoopAgent.
Split provider JSON helper from native tool model (remove JSON-only transform
for the latter). Preserve returned SDK messages/provider metadata, structured
tool outcomes, usage and evidence per step. `isStepCount(1)` per slice persists
the logical loop; model chooses the next tool from observed state/results.
Explicit system instructions and structured current requests/context/history/
draft/dependencies/budgets. Do not expose private reasoning in shared chat.
Tools: read authorized context, edit request, resolve/submit recipe, search/read
products, select known evidence, calculate/validate draft, publish draft or ask
targeted question. Application evidence marks completion, not model text.
Targeted questions pause and recipient replies resume without replaying all
work. Draft readiness and approval remain server-owned.

Enforce all global bounds, typed transient/auth/stale/no-match outcomes,
exponential backoff respecting Retry-After, persisted next attempt, partial
progress/no-progress stopping. Refresh per-person context and invalidate only
affected artifacts. Model or MCP absence becomes explicit blocked status, not
fake success. Use Host only for commerce. No speculative live model calls.

Replace `party-runner.ts` entry point with v2 dispatch under a version flag;
legacy remains read-only rollback/shadow, never competing writers. Existing
Node internal worker route owns work. Edge dispatcher acknowledges quickly and
uses bounded background work; durable queue/lease supports crash recovery.
Provide a local polling npm command using the same worker route and a documented
5-second Cron dispatcher configuration without embedding deployment secrets.
User action paths should enqueue, not synchronously finish a whole model loop.
Refactor harness to execute the same v2 tools and loop using injectable fixture
adapters; no divergent fake demonstration pipeline. Preserve harness auth guards.

Test real tool-roundtrip with mock language model, intermediate failure/replan,
checkpoint resume, limits, no-progress, stale lease, question resume and failure
classification; test native request format. Use installed SDK/Next docs. Record
integration APIs for Task 4. Full tests once before reporting.

## Task 4: Wire every input and UI to one revision-bound approval flow

Update `src/app/parties/actions.ts`, profile actions, party workspace loading,
party page, realtime shell/state and necessary components to Task 3 API.
Every intent/chat/manual add/update/delete/budget/profile/member change creates
an authenticated atomic source event and queues affected work. No global
all-participants gate. Use typed edits/stable targets rather than flattened text.
Do not allow model edits to impersonate another participant or bypass roles.
Manual Add/Delete is draft-only. Remove legacy sync/send/create/confirm bypasses;
only exact ready draft Host approval calls Task 2 reconciliation. Keep existing
basket as applied history/baseline; existing old proposals are not auto-ready.
New approvals are bound to immutable revision and server role checks.

Show provisional/ready/stale/blocked/waiting/applied distinctions, actionable
public-safe blockers, accurate real steps (no fake pre-advanced stages), draft
items/quantities/totals, Host approval revision and participant-private questions.
Reconnect reads authoritative current state. Server access and RLS protect
private profiles/messages; not just hiding them client-side. Budget/profile
changes replan; question replies resume the appropriate run.

Test all former write entrypoints, host/nonhost/stale approval, private messages,
incremental participation, manual changes and reconnect behavior using focused
tests before implementation. Check relevant Next guides before changes.
Run full tests, lint and build before reporting. Never remotely apply migrations.

## Task 5: Evaluation, observability, rollout documentation and integration audit

Instrument v2 run/step/operation/revision IDs, model/prompt versions, usage,
latency, evidence IDs, tool failure category/retries and terminal outcomes.
Raw prompts/responses/private profiles must be off in telemetry by default.
Add optional Langfuse using current AI SDK 7 integration, disable input/output
recording by default and isolate telemetry failures from agent/cart behavior.

Create at least 50 explicitly described fixture scenarios covering direct edits,
group context, recipe provenance, stock/variant/units/budget, recovery and roles.
Run through production domain/loop via shared harness, not an unrelated mock
algorithm. Model-dependent eval runner supports 3 trials old/new against same
fixture set and reports success/unauthorized writes/private leaks/cost/latency.
Distinguish deterministic fixture success from actual model eval success; a
correct blocker only succeeds where expected. Tests must assert real behavior.

Document local setup/migration/worker/dispatcher/Cron, read-only tools/list and
model smoke tests, dedicated-cart acceptance test, engine version feature flag,
read-only shadow and safe rollback preserving ledger/drafts/cart. State live
checks not executed here; no invented >=90% claim. Target zero unauthorized
writes/leaks, >=90% task eval, <1s enqueue and <20s simple-product latency are
release gates, not claims. Provide deployment checklist and verification commands.

Audit end-to-end wiring against all constraints, fix integration issues within
scope, run full npm tests, lint, build, Python harness tests where still relevant
and local DB security/concurrency checks if database available. Do not apply
remote migrations or touch live carts. Report unresolved environment prerequisites.
